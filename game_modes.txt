ON BEAT — GAME MODES & FEATURES NOTES
======================================

DIFFICULTY LEVELS (separate axis from mode)
--------------------------------------------
Applied to pattern pool in _generateRandomMeasure().

  EASY   → [8, 10, 12, 15]
             8  = 1000 = single hit on beat 1 (downbeat)
             10 = 1010 = hits on beat 1 and 3 (straight 8th feel)
             12 = 1100 = hits on beat 1 and 2 (two consecutive 16ths)
             15 = 1111 = all four 16ths (straight 16ths)
             → clear, on-beat patterns, no syncopation

  MEDIUM → [8, 10, 12, 15, 0, 9, 13, 14, 11, 7]
             0  = terzina (triplet: hits at 0, 1/3, 2/3)
             9  = 1001 = hits on beat 1 and 4 (starts syncopating)
             13 = 1101 = hits on 1, 2, 4
             14 = 1110 = hits on 1, 2, 3
             11 = 1011 = hits on 1, 3, 4
             7  = 0111 = hits on 2, 3, 4
             → adds triplet feel and mild syncopation

  HARD   → all patterns [0..15]
             adds fully syncopated patterns:
             1  = 0001 = hit on beat 4 only
             2  = 0010 = hit on beat 3 only
             3  = 0011 = hits on 3 and 4
             4  = 0100 = hit on beat 2 only
             5  = 0101 = hits on 2 and 4 (very syncopated)
             6  = 0110 = hits on 2 and 3
             → every possible 16th note combination


GAME MODES
----------

  NORMAL (implemented)
    - Fixed lives (currently 10)
    - Fixed BPM (currently 60)
    - Fixed difficulty
    - Ends when lives reach 0

  ZEN (implemented, TESTED — works)
    - Infinite lives
    - Fixed BPM
    - No pressure, just practice
    - Has a Stop button (added after testing — no auto-end condition)

  INCREMENTAL (implemented, TESTED — works, cool)
    - Starts at startBpm (default 60), configurable via constructor
    - BPM increases +5 every 4 measures (_bpmStep, _measuresPerStep constants)
    - Ends on 3 consecutive quarter misses (_maxConsecutiveMisses = 3)
      or when _maxBpm (200) is reached → maxBpmReached = true
    - UI should show current BPM (ExerciseController.currentBpm getter)
      and "max BPM reached!" banner when maxBpmReached is true

  SURVIVAL (implemented, NOT TESTED)
    - Starts with 3 lives (_survivalStartLives), max capped at 5 (_survivalMaxLives)
    - Every quarter miss costs 1 life
    - Every perfect streak of 4 consecutive perfects (_streakForLife) gives 1 life back
      → ok resets the perfect streak, miss also resets it
    - BPM increases +5 every 4 measures (same ramp as incremental)
    - Ends when lives reach 0
    - UI should show: lives, perfectStreak getter, currentBpm getter

  CHALLENGE (implemented, NOT TESTED)
    - Fixed number of measures (default 16, configurable via challengeTotalMeasures)
    - No lives — just play through
    - Tracks perfect/ok/miss per quarter across all measures
    - Ends when challengeTotalMeasures completed → challengeComplete = true
    - Score exposed via: perfectCount, okCount, missCount, totalQuarters getters
    - UI should show a result screen when challengeComplete is true
      with score breakdown and % accuracy
